# ADR 0001：双后端——LLM 负责判断，离线规则保证可用

- 状态：已采纳（2026-09-22，用户选定）
- 背景：产品的核心价值（假设、矩阵、解读）天然适合 LLM；但 LLM 端点可能没配置、超时、返回垃圾。如果 LLM 是硬依赖，无网/无 key 时整个工具不可用，且本机测试只能靠 mock 覆盖不了真实链路。
- 决策：
  1. 后端协议统一（`DesignBackend.design/analyze`），LLM 与离线启发式是两个实现；
  2. 离线后端确定性：模板假设 + 网格矩阵 + §12.3 规则（边界外推/区间收窄）；
  3. LLM 输出必须过 pydantic 校验（严格 JSON、重试一次）；失败 → 降级离线并在 `fallback_reason` 记录原因——**降级不是静默**；
  4. `--backend llm` 未配置时直接报错（显式意图不降级）；`auto` 才允许降级并提示。
     - 补充（2026-10-20 实现确认）：显式 `--backend llm` 在**调用失败时同样直接报错**（不只是「未配置」时报错），错误信息给出替代方案（`--backend offline` / `--backend auto`）；LLM 不可用时不允许静默换成离线结果。
     - 补充：`auto` 循环沿用 study 记录的后端时允许降级（`allow_fallback=True`）——整晚的实验不该因为 LLM 掉线而丢掉已跑完的结果，降级原因写进 `fallback_reason` 并出现在报告里。
- 理由：可离线、可测试（MockTransport + 本地假服务器覆盖真实 httpx 路径）、可解释（LLM 建议与规则建议写进同一结构，来源标注）。
- 代价：离线模式的分析较模板化；两条路径的行为差异需要测试同时覆盖。
